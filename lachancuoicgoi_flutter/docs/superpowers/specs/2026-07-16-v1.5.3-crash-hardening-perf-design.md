### 3B. Catch block hardening — thêm guard + telemetry

24 catch block hiện chỉ `warning()` rồi fallback im lặng. Không thay đổi behavior graceful-degradation, nhưng:

| Cải thiện | Cách làm |
|-----------|----------|
| Đếm fallback次数 | Thêm static counter `_fallbackCount` cho mỗi subsystem — expose qua health check service |
| Surface cho user | Khi fallback xảy ra ≥3 lần trong 1 session → hiển thị banner "Chế độ giảm thiểu đang hoạt động" (đã có `HealthCheckService`) |
| Guard rõ ràng | Mỗi catch thêm comment `// GRACEFUL-DEGRADATION: <lý do>` để phân biệt với bug thật |

### 3C. Tối ưu asset loading

| Vấn đề | Sửa |
|--------|-----|
| TFLite model (`ghitav3.tflite`) + Vosk model (`model-vn/`) load đồng thời khi app start → memory spike trên thiết bị 3GB RAM | Lazy load theo tier: L1 trie load ngay (nhẹ), TFLite load khi user vào monitoring lần đầu, Vosk load khi monitoring bắt đầu |
| JSON assets (12 file) parse sync trên UI thread | Wrap `jsonDecode` trong `compute()` cho file >50KB (`risk_scenarios_master.json`, `vocabulary_ai_check.json`) |
| `_loadString` không cache — parse lại mỗi lần | Thêm cache Map trong `AssetLoader` — parse 1 lần, reuse |

### 3D. Tối ưu UI rebuild

| Vấn đề | Sửa |
|--------|-----|
| `monitoring_page.dart` dùng `ref.watch(monitoringControllerProvider)` ở root → toàn bộ widget tree rebuild khi state đổi | Tách thành `ref.watch` chỉ ở nhánh cần (transcript list, risk indicator, status) — dùng `select` để chỉ listen field cụ thể |
| Transcript list dùng `SingleChildScrollView` (build toàn bộ) → jank khi transcript dài | Đổi sang `ListView.builder` (lazy build) + `itemExtent` nếu dòng cố định chiều cao |
| `AnimatedBuilder` rebuild trên mỗi RMS sample (16ms) | Tách RMS animation ra `RepaintBoundary` + `ValueListenableBuilder` riêng — không rebuild parent |

### 3E. Tối ưu pipeline analysis

| Vấn đề | Sửa |
|--------|-----|
| `_l3Timeout = 1800ms` cố định — quá dài cho thiết bị cấp thấp | Thêm adaptive timeout: đo RTT lần đầu, set timeout = RTT × 2 (min 800ms, max 1800ms) |
| `response_cache.dart` + `lru_cache.dart` dùng `Map` + `_cache.keys.first` (O(n) eviction) | Đổi sang `LinkedHashMap` với `remove` O(1) |
| `_minDeltaDefault = 50` chars cố định — quá lớn cho STT chậm, quá nhỏ cho STT nhanh | Adaptive delta dựa trên `_speechRate`: STT chậm → delta nhỏ hơn (phân tích sớm hơn) |

### 3F. Tối ưu Kotlin native

| Vấn đề | Sửa |
|--------|-----|
| `BackgroundMonitoringService` dùng `Dispatchers.IO` cho tất cả coroutine — bao gồm cả UI update | Tách: `Dispatchers.IO` cho audio/STT, `Dispatchers.Main` cho overlay update |
| Vosk `Model` + `Recognizer` giữ static trong companion object → memory leak khi service destroy | Đảm bảo `release()` trong `onDestroy` + set null trong companion |
| `SpeechToTextManager` poll audio buffer mỗi 16ms → CPU spike | Batch read: đọc buffer 3 lần (48ms) rồi process 1 lần — giảm ⅔ callback overhead |

## Rủi ro & mitigation

| Rủi ro | Mitigation |
|--------|------------|
| Refactor lớn gây regression | Chia commit nhỏ, chạy test sau mỗi file tách. Nếu test fail → revert file đó, thử lại |
| Tối ưu asset loading thay đổi init order → race condition | Giữ lazy load với guard `if (_loaded) return` — init idempotent |
| Kotlin refactor break native bridge | Test platform channel sau mỗi thay đổi Kotlin (Luồng 1) |
| TFLite/Vosk lazy load chậm lần đầu monitoring | Hiển thị loading indicator "Đang tải model AI..." khi user vào monitoring |
| Obfuscate break stack trace deobfuscation | Giữ `mapping.txt` + `symbols-v1.5.3/` cẩn thận, không xóa |
